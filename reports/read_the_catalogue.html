Reading the QuakeScope pick catalogue¶

Machine-learning phase picks for the western United States, as Parquet on S3. No credentials, no database, no account — the catalogue is public-read and every cell below runs anonymously.

This notebook:

  1. installs what it needs (about a minute on a cold Colab runtime),
  2. reads picks straight from S3 with partition pruning,
  3. plots what is in them,
  4. re-queries the original waveforms from FDSN with ObsPy and draws the picks on top, so you can see what the model saw.
bucket s3://quakescope-picks-2026 (us-east-2, public-read)
layout <campaign>/picks/network=<NET>/year=<YYYY>/month=<MM>/*.parquet
provenance <campaign>/runs/<rid>.json — model, weight, thresholds

Nothing here writes to S3, and nothing needs an AWS account.

What the columns mean¶

column meaning
tid trace id, NET.STA.LOC
cha channel band (HH, BH, EH, HN) — one band per station-day
pha P or S
start, peak, end pick window; peak is the arrival time
conf model confidence, 0–1. Everything stored is above 0.2
amp Wood-Anderson amplitude, metres — for local magnitude
amp_raw peak amplitude in raw counts, before response removal
rid run id → runs/<rid>.json for the model and thresholds used

conf is a detection score, not a probability of correctness. The stored floor of 0.2 is deliberately permissive so you can choose your own threshold; most analyses want considerably more than that.

The daily curve is the useful sanity check: P and S should track each other, and a day where one collapses is usually a data outage rather than a quiet Earth. The spikes are real sequences.

4. Re-query the waveforms and check the picks¶

Picks are only as good as they look on the record. The catalogue stores no waveforms, so fetch them from the SCEDC FDSN service with ObsPy — the same data the picker read, from the archive of record.

Take the busiest station-minute in the month.

In [6]:
import obspy
from obspy.clients.fdsn import Client

picks["minute"] = picks["peak"].dt.floor("min")
tid, minute = picks.groupby(["tid", "minute"]).size().idxmax()
net, sta, loc = tid.split(".")
print(f"{tid}  {minute}")

t0 = obspy.UTCDateTime(minute) - 10
st = Client("SCEDC", timeout=60).get_waveforms(
    network=net, station=sta, location=loc or "*", channel="HH?",
    starttime=t0, endtime=t0 + 80,
)
st.detrend("demean").filter("bandpass", freqmin=2, freqmax=20)
print(st)

6. Reading it at scale¶

One month of one network is 0.5M picks and reads in seconds. The finished campaign will not. Measured on what is written so far, and projected:
picks per station-day ~996
bytes per pick, compressed 31.4
planned station-days 112.9M
projected catalogue ~112 billion picks, ~3.5 TB

At that size the thing that hurts is not bytes, it is files. Reading a Parquet dataset means opening every file's footer to learn what is in it, and that cost is paid per object however small your query. Timed against the current scedc data — 514 objects, 0.44 GB:

approach whole catalogue
pyarrow.dataset discovery + count 78.7 s
DuckDB 14.5 s

Same data, same S3, 5.4x. Scale that gap to hundreds of thousands of objects and it is the difference between a query and an afternoon.

Three rules, in order of how much they save.

1. Always filter on the partition columns¶

network, year and month come from the path. Filtering on them skips whole files without opening them; filtering on anything else opens the file first. This is the single biggest lever.

In [10]:
import duckdb, time

con = duckdb.connect()
con.sql("INSTALL httpfs; LOAD httpfs; SET s3_region='us-east-2';")
# Anonymous: empty credentials, the DuckDB equivalent of anon=True.
con.sql("SET s3_access_key_id=''; SET s3_secret_access_key='';")

ROOT = f"s3://{BUCKET}/scedc/picks/**/*.parquet"

t0 = time.time()
pruned = con.sql(f"""
    SELECT count(*) FROM read_parquet('{ROOT}', hive_partitioning=1)
    WHERE network='CI' AND year=2014 AND month=9
""").fetchone()[0]
print(f"pruned to one partition: {pruned:,} picks in {time.time()-t0:.1f}s")

pruned to one partition: 509,837 picks in 1.9s

2. Aggregate in the query, not in pandas¶

.df() materialises everything into memory. A count, a histogram or a per-station summary should come back already reduced — the catalogue is far larger than any laptop, and most questions do not need the rows themselves.

In [11]:
busiest = con.sql(f"""
    SELECT tid,
           count(*)                        AS picks,
           count(*) FILTER (pha='S')       AS s_picks,
           round(avg(conf), 3)             AS mean_conf
    FROM read_parquet('{ROOT}', hive_partitioning=1)
    WHERE network='CI' AND year=2014
    GROUP BY tid
    ORDER BY picks DESC
    LIMIT 10
""").df()

3. Select only the columns you need¶

Parquet is columnar, so an unused column costs nothing to skip — but only if you say so. SELECT * reads the amplitude columns even when you only wanted arrival times.

And the one that is not yours to fix: file size¶

A shard writes its own Parquet objects, so a partition accumulates many small files. Compaction consolidates them once a campaign passes 80% complete (sb_catalog.src.parquet_compact), and on a test partition it cut 32 objects to 1. Query time scales with object count, so a compacted campaign is markedly faster to read than a running one. If a query feels slow, check whether that campaign has compacted yet.

6. Going further¶

Other campaigns. Swap scedc in the path for ncedc, earthscope, western or obs. Coverage differs — see the dashboard for what has been written so far.

Bigger than memory. DuckDB will push filters down and never materialise the whole catalogue:

import duckdb
duckdb.sql("INSTALL httpfs; LOAD httpfs; SET s3_region='us-east-2';")
duckdb.sql(f'''
    SELECT tid, count(*) n, avg(conf) conf
    FROM read_parquet('s3://quakescope-picks-2026/scedc/picks/**/*.parquet',
                      hive_partitioning=1)
    WHERE network='CI' AND year=2014
    GROUP BY tid ORDER BY n DESC LIMIT 20
''').df()

Choosing a threshold. Everything above conf 0.2 is stored, which is far more permissive than most uses want. Raise it and check the effect on your own target events rather than adopting a number from elsewhere.

Associating into events. These are per-station picks, not locations. A phase associator (GaMMA, PyOcto) turns them into events.

Amplitudes. amp is Wood-Anderson displacement in metres, ready for local magnitude. amp_raw is pre-response counts, useful mainly for QC.
