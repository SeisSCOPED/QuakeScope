Waveforms and picks

Picks drawn at random from the catalogue each hour, with the waveform they were made on. Only picks at confidence ≥ 0.5 are shown - the picking threshold is 0.2, so most of the catalogue is marginal and a uniform sample would mostly show that. Colour is the phase; the number is confidence. Traces are demeaned and high-passed at 1 Hz for display only - the picks were made upstream, on the data the model saw.

Campaign plan

What is still to run, costed from one measured rate: 0.0241 vCPU-hours per station-day (707 vCPU-hours over 10,440 station-days on the live SCEDC campaign, times 0.354 for the short-window amplitude rework). Time assumes the full 12,000-vCPU Fargate Spot quota with nothing else running. These are projections, not observations - the tiles above are what actually happened.

Two figures, and the difference is the hit rate. The rate above is per station-day processed; the plan counts station-days planned, and most planned days hold no data - measured hit rates run 21.7% to 67.6%. The upper bound column assumes every planned day has data; the expected column applies a 40% hit rate. The authoritative model, 24_cost_model.md, puts the campaign at $10,828-$19,702 and says which end depends on that one unmeasured number.

Nothing is blocked. The EarthScope restricted access point was never stalling: the credential request was unscoped, so it could LIST but not GET, and every read returned AccessDenied instantly. Scoping it to network=FDSN:<NET> fixed it, and restricted reads now run at 96-98 MB/s - the same rate as Open Data.

Two things the plan still carries that will not produce picks: ~3.67M station-days on network-years EarthScope does not hold, which complete empty and are harmless; and 49 networks that answer 403, which were dropped from global on 2026-09-03 and can be restored if EarthScope grants access.

Where the catalogue lives

Public-read, no account needed. The picks are Parquet on S3, Hive-partitioned by network, year and month. Read them with anything that speaks Parquet; there is no database to connect to and no credentials to obtain. claims/ and progress/ are internal and stay private; picks, manifests and run provenance are open.

# ---------------------------------------------------------------
import pandas as pd

# anon=True is REQUIRED and is the whole point: the read is
# unauthenticated. Without it pandas looks for credentials that a
# reader has no reason to have, and fails before reaching S3.
ANON = {"anon": True}

# one month, with partition pruning - only matching files are fetched
df = pd.read_parquet(
    "s3://quakescope-picks-2026/global/picks/",
    filters=[("network", "=", "CI"), ("year", "=", 2014), ("month", "=", 9)],
    storage_options=ANON,
)

# which model made them, and at what thresholds
import json, urllib.request
run = json.load(urllib.request.urlopen(
    "https://quakescope-picks-2026.s3.us-east-2.amazonaws.com/global/runs/"
    + df["rid"].iloc[0] + ".json"))

# or exactly the objects one shard wrote, from its manifest
m = json.load(urllib.request.urlopen(
    "https://quakescope-picks-2026.s3.us-east-2.amazonaws.com/global/manifests/<shard>.json"))
df = pd.concat(pd.read_parquet(f["path"], storage_options=ANON)
               for f in m["files"])

Columns. tid trace id NET.STA.LOC · cha band · pha P or S · peak the arrival time · conf model score, floored at 0.2 · amp Wood-Anderson displacement in metres · amp_raw peak counts before response removal · rid run id, joins to runs/. conf is a detection score, not a probability of correctness; the 0.2 floor is permissive on purpose so you can pick your own threshold.

Two pick counts, both true. The tile counts picks in shards that have finished, taken from their manifests. A running shard checkpoints its work to Parquet every 40 station-day-channels, so the objects on S3 already hold more than the tile shows; the manifest only appears when the shard closes. Query the Parquet for what is actually stored, the tile for what is durably accounted for. Every figure above except spend is counted from an S3 or Batch API response. Spend is derived: vCPU-hours from Batch job start and stop times, multiplied by $0.0148 per vCPU-hour. It is not a billed figure — Cost Explorer is blocked on this account by an organisation policy, so nothing here has been checked against AWS billing. Data volume ingested from the archives is not shown because it is not measured anywhere; the catalogue size above is what was written, not what was read.
