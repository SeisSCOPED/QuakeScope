Waveforms and picks

Picks drawn at random from the catalogue each hour, with the waveform they were made on. Only picks at confidence ≥ 0.5 are shown - the picking threshold is 0.2, so most of the catalogue is marginal and a uniform sample would mostly show that. Colour is the phase; the number is confidence. Traces are demeaned and high-passed at 1 Hz for display only - the picks were made upstream, on the data the model saw.

Where the catalogue lives

The picks are Parquet on S3, Hive-partitioned by network, year and month. Read them with anything that speaks Parquet; no database to connect to.

buckets3://quakescope-picks-2026
regionus-east-2
pickss3://quakescope-picks-2026/<campaign>/picks/network=<NET>/year=<YYYY>/month=<MM>/<shard>.parquet
manifestss3://quakescope-picks-2026/<campaign>/manifests/<shard>.json
run metadatas3://quakescope-picks-2026/<campaign>/runs/<run_id>.json
import pandas as pd

# one campaign, with partition pruning - no LIST, no scan
df = pd.read_parquet(
    "s3://quakescope-picks-2026/scedc/picks/",
    filters=[("network", "=", "CI"), ("year", "=", 2019)],
)

# or exactly the objects a shard wrote, from its manifest
import json, boto3
m = json.load(boto3.client("s3", region_name="us-east-2").get_object(
    Bucket="quakescope-picks-2026", Key="scedc/manifests/<shard>.json")["Body"])
df = pd.concat(pd.read_parquet(f["path"]) for f in m["files"])
Two pick counts, both true. The tile counts picks in shards that have finished, taken from their manifests. A running shard checkpoints its work to Parquet every 40 station-day-channels, so the objects on S3 already hold more than the tile shows; the manifest only appears when the shard closes. Query the Parquet for what is actually stored, the tile for what is durably accounted for. Every figure above except spend is counted from an S3 or Batch API response. Spend is derived: vCPU-hours from Batch job start and stop times, multiplied by $0.0148 per vCPU-hour. It is not a billed figure — Cost Explorer is blocked on this account by an organisation policy, so nothing here has been checked against AWS billing. Data volume ingested from the archives is not shown because it is not measured anywhere; the catalogue size above is what was written, not what was read.
